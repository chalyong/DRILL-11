# Character Controller: Auto Run PRD

## 1. 문서 개요

### 1.1 목적

소년 캐릭터가 `idle` 상태에서 `A` 키를 누르면 일정 시간 동안 자동으로 달리는
`auto run` 상태로 전환되도록 캐릭터 컨트롤러를 확장한다.

### 1.2 대상 범위

- 대상 프로젝트: `LEC12_CharacterController`
- 대상 캐릭터: `Boy`
- 주요 변경 대상: `boy.py`
- 연관 코드: `main.py`의 이벤트 전달 및 게임 루프
- 환경: Pico2D, `transitions.Machine`

### 1.3 제외 범위

- 새로운 스테이지, 적, 점수, UI 추가
- 이미지 리소스 교체
- 기존 `sleep` 상태의 동작 변경
- 자동 달리기 중 별도의 사운드나 이펙트 추가

## 2. 현재 동작

`Boy`는 현재 다음 상태를 가진다.

- `IDLE`: 제자리에서 애니메이션을 재생하며, 일정 시간이 지나면 `SLEEP`으로 전환
- `RUN`: 좌우 방향키 입력을 받은 방향으로 이동
- `SLEEP`: 누워 있는 애니메이션을 표시하며, 스페이스 키로 깨어남

`main.py`는 모든 키보드 이벤트를 `boy.handle_event(event)`로 전달하고, 매 프레임
`boy.update()`와 `boy.draw()`를 호출한다. 따라서 자동 달리기는 별도의 게임 루프를
추가하지 않고 `Boy`의 상태·이벤트·업데이트·렌더링 로직으로 구현한다.

## 3. 요구사항

### 3.1 자동 달리기 진입

1. 소년의 현재 상태가 `IDLE`일 때 `A` 키(`SDLK_a`)를 누르면 `AUTO_RUN` 상태로
   전환한다.
2. `AUTO_RUN` 진입 시 자동 달리기 타이머를 시작한다.
3. 자동 달리기 시작 방향은 진입 시점의 `face_dir`를 사용한다.
   - 오른쪽: `face_dir = 1`
   - 왼쪽: `face_dir = -1`
4. 자동 달리기 상태는 반드시 기존 상태와 구분되는 상태 클래스로 추가한다.
   - 상태 머신을 유지하는 경우 `AutoRun` 상태 클래스를 추가하고 `AUTO_RUN` 상태와
     연결한다.
   - 단순 문자열 분기만 추가하여 기존 `RUN` 상태를 재사용하는 방식은 허용하지 않는다.

### 3.2 자동 이동

1. `AUTO_RUN` 상태에서는 방향키 입력 없이도 매 프레임 캐릭터가 이동한다.
2. 이동 방향은 `face_dir`를 따른다.
3. 자동 달리기 속도는 기존 `RUN` 속도보다 커야 한다.
   - 기존 기준 속도: `RUN_SPEED = 5`
   - 권장 값: `AUTO_RUN_SPEED = 15`
4. 이동 좌표는 화면 안에서만 유지한다.

### 3.3 화면 끝 방향 전환

1. 소년의 중심 좌표가 왼쪽 이동 한계(`MIN_X`)에 도달하면 즉시 오른쪽을
   바라보고 이동한다.
2. 소년의 중심 좌표가 오른쪽 이동 한계(`MAX_X`)에 도달하면 즉시 왼쪽을
   바라보고 이동한다.
3. 방향 전환 시 `x` 좌표는 `MIN_X` 또는 `MAX_X`를 넘지 않아야 한다.
4. 화면 끝에 도달한 프레임에서 방향을 변경하므로, 다음 업데이트부터 반대 방향으로
   이동한다.

### 3.4 자동 달리기 종료

1. `AUTO_RUN` 진입 후 5초가 지나면 `IDLE` 상태로 전환한다.
2. 5초 판정은 프레임 수가 아니라 `pico2d.get_time()` 기반의 경과 시간으로
   처리한다.
3. `IDLE` 복귀 시 자동 달리기 타이머를 초기화한다.
4. `IDLE` 복귀 직후 기존 idle 타이머 때문에 즉시 `SLEEP`으로 전환되지 않도록
   idle 시작 시각을 복귀 시점으로 갱신한다.
5. 자동 달리기 종료 시 프레임은 idle 애니메이션의 시작 프레임으로 초기화한다.

### 3.5 방향키 입력에 의한 취소

1. `AUTO_RUN` 중 왼쪽 또는 오른쪽 방향키를 누르면 자동 달리기를 즉시 취소한다.
2. 자동 달리기 취소와 동시에 눌린 방향으로 `RUN` 상태가 된다.
3. 방향키 입력 방향을 `face_dir`에 반영한 뒤 `RUN`으로 전환해야 한다.
4. 이후 방향키를 계속 누르고 있는 동안에는 기존 `RUN` 동작을 유지한다.
5. 모든 방향키를 놓으면 기존 동작과 동일하게 `IDLE`로 전환한다.
6. `A` 키의 `KEYUP` 이벤트는 자동 달리기를 취소하지 않는다.

### 3.6 다른 상태와의 상호작용

- `SLEEP` 상태에서 `A` 키를 눌러도 `AUTO_RUN`으로 전환하지 않는다.
- `RUN` 상태에서 `A` 키를 눌러도 현재 방향키 이동을 중단하거나 자동 달리기로
  바꾸지 않는다. 자동 달리기 진입 조건은 `IDLE` 상태에서의 입력으로 한정한다.
- `SPACE` 키에 의한 `SLEEP -> IDLE` 전환은 기존과 동일하게 유지한다.
- 자동 달리기 중 `SPACE` 키는 별도 동작을 하지 않는다.

## 4. 상태 및 전이 설계

### 4.1 상태 목록

| 상태         | 설명                                        |
| ------------ | ------------------------------------------- |
| `IDLE`     | 제자리 대기 및 idle 애니메이션              |
| `RUN`      | 방향키를 누르는 동안 수동 이동              |
| `AUTO_RUN` | 방향키 없이 일정 시간 동안 빠르게 자동 이동 |
| `SLEEP`    | 수면 애니메이션                             |

### 4.2 전이 표

| 현재 상태    | 트리거              | 다음 상태    | 후처리                                    |
| ------------ | ------------------- | ------------ | ----------------------------------------- |
| `IDLE`     | `A` 키 다운       | `AUTO_RUN` | 자동 달리기 시작 시각 기록, 프레임 초기화 |
| `AUTO_RUN` | 5초 경과            | `IDLE`     | idle 타이머·프레임 초기화                |
| `AUTO_RUN` | 왼쪽 키 다운        | `RUN`      | 왼쪽 방향 설정, 수동 이동 시작            |
| `AUTO_RUN` | 오른쪽 키 다운      | `RUN`      | 오른쪽 방향 설정, 수동 이동 시작          |
| `IDLE`     | 방향키 다운         | `RUN`      | 입력 방향 설정                            |
| `SLEEP`    | 스페이스 키 다운    | `IDLE`     | idle 타이머 초기화                        |
| `RUN`      | 모든 방향키 업      | `IDLE`     | idle 타이머·프레임 초기화                |
| `IDLE`     | idle 제한 시간 경과 | `SLEEP`    | 수면 자세 초기화                          |

## 5. 애니메이션 및 렌더링

### 5.1 자동 달리기 애니메이션

- `AUTO_RUN`은 `RUN`과 구분되는 렌더링 분기를 가져야 한다.
- 자동 달리기 시 기존 달리기 스프라이트 행을 사용하되, 현재 `RUN`보다 크게
  그린다.
- 권장 렌더링 크기:
  - 일반 `IDLE`/`RUN`: `100 x 100`
  - `AUTO_RUN`: `120 x 120`
- 확대 시 캐릭터의 중심이 기존 위치와 크게 어긋나지 않도록 동일한 기준점
  (`self.x`, `self.y`)을 사용한다.
- 방향에 따른 스프라이트 행 선택은 기존 `RUN`과 동일한 규칙을 따른다.
- 자동 달리기 프레임은 `AUTO_RUN` 상태에서 독립적으로 순환한다.

### 5.2 화면 경계와 확대 렌더링

현재 이동 경계는 일반 프레임 폭을 기준으로 한다. 자동 달리기 캐릭터를 확대해
그리는 경우에도 캐릭터가 화면 밖으로 잘리지 않도록 다음 중 하나를 구현한다.

1. 자동 달리기 렌더링 폭을 반영해 별도의 `AUTO_MIN_X`/`AUTO_MAX_X`를 계산한다.
2. 기존 경계를 유지하되 확대 크기와 경계의 차이를 허용 범위 내에서 검증한다.

권장 방식은 실제 자동 달리기 렌더링 폭을 기준으로 경계를 계산하는 것이다.

## 6. 구현 지침

### 6.1 `boy.py`

- `AUTO_RUN` 상태 상수와 자동 달리기 지속 시간·속도·렌더링 크기 상수를 추가한다.
- `AutoRun` 상태 클래스를 추가하고 상태 머신에 등록한다.
- 자동 달리기 시작·종료 전용 전이 또는 콜백을 추가한다.
- `update()`에서 자동 달리기 시간 만료를 이동보다 먼저 확인한다.
  - 같은 프레임에 5초가 만료된 경우 추가 이동 없이 `IDLE`로 복귀한다.
- `handle_event()`에서 `SDLK_a`를 처리하고, 자동 달리기 중 방향키 입력을
  `RUN` 전환으로 연결한다.
- 기존 `IDLE`, `RUN`, `SLEEP` 동작과 공통 상수·헬퍼를 우선 재사용한다.
- 방향키 집합(`pressed_directions`)을 사용할 때 자동 달리기 취소와 기존
  키 업 처리 순서가 충돌하지 않도록 한다.

### 6.2 `main.py`

- 게임 루프와 이벤트 전달 구조는 유지한다.
- `Boy.handle_event()`에서 자동 달리기 입력을 처리할 수 있으므로, 자동 달리기
  전용 전역 플래그나 별도 루프를 추가하지 않는다.

### 6.3 오류 처리 및 호환성

- 상태 머신에 등록되지 않은 전이를 호출하지 않는다.
- 자동 달리기 진입·종료 시 상태와 타이머를 일관되게 갱신한다.
- 기존 키 조작, 수면, 화면 경계 동작을 회귀시키지 않는다.

## 8. 권장 구현 순서

1. `AUTO_RUN` 상태 및 `AutoRun` 상태 클래스를 정의한다.
2. 상태 머신에 자동 달리기 진입·종료·수동 달리기 전이를 등록한다.
3. 자동 달리기 타이머와 속도 기반 이동을 `update()`에 추가한다.
4. 화면 경계 도달 시 방향 전환을 추가한다.
5. `A` 키와 자동 달리기 중 방향키 이벤트를 추가한다.
6. 자동 달리기 전용 확대 렌더링을 추가한다.
7. 자동 달리기 종료 후 idle 타이머 초기화와 기존 동작 회귀를 검증한다.

## 9. 점진적 개발 및 커밋 전략

### 9.1 목표

기능을 한 번에 크게 구현하지 않고, 각 단계가 검증 가능한 작은 변경이 되도록
분리한다. 개발 과정에서 **20개 이상의 의미 있는 커밋**을 남기며, 각 커밋은
하나의 목적만 포함하고 이전 단계의 동작을 깨뜨리지 않아야 한다.

커밋은 단순히 커밋 수를 늘리기 위한 빈 커밋이나 의미 없는 파일 수정으로 만들지
않는다. 각 커밋 후에는 가능한 범위의 테스트 또는 정적 검증을 수행하고, 커밋
메시지는 변경 목적을 설명하는 명령형 형식으로 작성한다.

### 9.2 커밋 원칙

- 기능 단위로 하나씩 커밋한다.
- 각 커밋은 빌드·구문 검사 가능한 상태를 유지한다.
- 서로 의존하는 커밋은 구현 순서대로 작성한다.
- 기능 구현 커밋과 테스트·문서 커밋을 구분한다.
- 기존 동작을 변경하는 경우 해당 커밋의 검증 방법을 함께 기록한다.
- 커밋 전 `git diff --check`로 공백 오류를 확인한다.
- 최종 단계에서 전체 변경 내역과 완료 기준을 다시 검증한다.

### 9.4 단계별 검증 기록

각 커밋을 생성할 때 다음 정보를 커밋 본문 또는 개발 기록에 남긴다.

1. 이번 커밋에서 변경한 기능
2. 확인한 테스트 시나리오 ID
3. 테스트 결과 또는 수동 확인 결과
4. 다음 커밋에서 해결할 단일 목표

최종적으로 다음 명령으로 커밋 수와 변경 범위를 확인한다.

```text
git log --oneline --all
git diff <기준 커밋>..HEAD --stat
git status --short
```

최종 구현은 20개 이상의 점진적 커밋을 통해 `AUTO_RUN` 상태, 자동 이동,
경계 반전, 5초 종료, 방향키 취소, 확대 렌더링을 각각 추적할 수 있어야 한다.
